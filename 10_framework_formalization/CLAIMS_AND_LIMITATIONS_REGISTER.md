# Claims and Limitations Register

This file defines what the revised IEEE Access manuscript may and may not claim.

## Allowed Claims

### Framework Claim

Allowed:

> We propose a leakage-controlled operational robustness framework for evaluating financial fraud-detection models across feature leakage, temporal ordering, prevalence shift, calibration, and explanation stability.

Reason:

- The work now contains feature governance and five stress-test modules backed by saved CSV results.

### Leakage Claim

Allowed:

> Unsafe evaluation choices can inflate reported fraud-detection metrics.

Supported by:

- Unsafe SMOTE-before-split inflated AP by about `0.050` to `0.142` and MCC by about `0.127` to `0.472`.
- D3 ledger-state features inflated AP and MCC.

Avoid:

> All previous fraud-detection studies are invalid.

### Temporal Claim

Allowed:

> Chronological evaluation can substantially reduce apparent performance relative to random stratified splits, particularly on D2.

Supported by:

- D2 AP drops of `-0.245` and `-0.277`.

Avoid:

> All datasets show strong temporal degradation.

Reason:

- D3 degradation is weak/mixed.
- D1 has anonymized elapsed time.

### Prevalence Claim

Allowed:

> Fixed-model and fixed-threshold operating metrics are sensitive to fraud-prevalence shift.

Supported by:

- Precision ranges up to about `0.592`.
- Cost ranges up to about `1793` per 10,000 transactions.

Avoid:

> Higher fraud prevalence makes the model intrinsically better.

Reason:

- Some metrics change mathematically with the base rate.

### Calibration Claim

Allowed:

> Isotonic recalibration consistently improved probability quality as measured by Brier score and Expected Calibration Error.

Supported by:

- Isotonic was best for Brier and ECE in every dataset/model pair.

Avoid:

> Calibration always improves operational cost.

Reason:

- Cost impact was mixed.

### Explanation Claim

Allowed:

> Explanation stability is dataset-dependent; D2 and D3 top feature rankings were stable, while D1 was more protocol-sensitive.

Supported by:

- D2/D3 Top-5 Jaccard `1.000`.
- D1 LightGBM protocol instability `0.524`; D1 XGBoost protocol instability `0.248`.

Avoid:

> The feature importance analysis proves causal fraud drivers.

Reason:

- Native tree feature importance is model-based explanation, not causal inference.

## Required Limitations

The manuscript must include these limitations:

1. **D1 temporal limitation:** D1 contains anonymized elapsed transaction time rather than full calendar time, so D1 chronological analysis should be interpreted as pseudo-temporal/order robustness.

2. **D3 synthetic limitation:** D3 is generated by a simulator and may not capture all real mobile-money fraud dynamics.

3. **D3 cap limitation:** Several stress tests use a 1,000,000-row timeline-sampled D3 subset for runtime feasibility.

4. **Cost limitation:** The cost ratio is a transparent stress assumption and not a bank-specific loss model.

5. **Explanation limitation:** Feature importance reflects model behavior, not causal explanation.

6. **Generalization limitation:** The datasets are heterogeneous but do not cover every region, institution, channel, or fraud typology.

## IEEE Access Tone Rules

Use:

- "The results indicate..."
- "The framework quantifies..."
- "This finding suggests..."
- "Under the evaluated datasets and protocols..."

Avoid:

- "This proves..."
- "The model is optimal..."
- "Production-ready..."
- "Guaranteed..."
- "First ever..." unless supported by a careful literature review.

## Resubmission Warning

Do not submit the old manuscript with small edits.

The revised submission must look like a new, coherent framework paper:

- New title.
- New abstract.
- New introduction.
- New contribution bullets.
- New methodology framework.
- New results narrative.
- Explicit limitations.
- Reproducibility mapping.
